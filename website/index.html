The problem

An AI agent on your Mac runs with your full access. So does everything it installs, downloads or writes.

That Mac holds your credentials, private files, logged-in browser sessions and work data. One compromised package or one hostile web page is enough to put all of it within reach. Most people will never read the scripts their agents run, and they should not have to.

Six layers

What can go wrong, and what stops it

Each layer answers one risk. The descriptions below cover what the beta does now. The status table lists the limits.

  1. 1

    Risk An agent installs something malicious, such as a compromised npm or PyPI release or a fake skill.

    Install gate

    A local registry firewall checks each npm and PyPI download against a signed malware list and refuses listed releases. Skill and instruction files are checked for known bad patterns.

  2. 2

    Risk Allowed code behaves badly when it runs, such as an install script that sends your credentials out.

    Containment

    npm dependency install scripts run in a sandbox. Their network access goes through a local allowlist, and they cannot write to your shell or npm configuration. This works without knowing the package is bad.

  3. 3

    Risk Data leaves through any app on the machine, such as a connection to a malware host.

    Outbound control

    A network extension records each app's new connections with the process and its signing identity, and blocks hosts on a threat list.

  4. 4

    Risk An agent is steered by hostile content in a web page, document, email or tool result.

    Agent checks

    Hooks in Claude Code, Codex and Cursor hold recognizable credential access, exfiltration and dangerous commands before they run. BoxCop does not detect the injection itself. It checks what the agent tries to do next.

  5. 5

    Risk The machine is already weak, with outdated runtimes and apps.

    Machine health

    BoxCop inventories apps, Homebrew, Python, npm and runtimes, shows reviewed findings, and walks you through the fix for the ones it can update.

  6. 6

    Risk Too many alerts, so the user turns everything off.

    Smart triage

    A model that runs on your Mac explains held actions in plain language and reviews linked activity. It can add caution. It cannot grant access.

Smart triage

Quiet by default

Sandboxing everything breaks things. Prompting for everything teaches people to click Allow. BoxCop saves heavy protection for what is new or suspicious and lets ordinary work run.

  1. Step 1

    Deterministic signals decide most cases

    Known-bad is blocked. Long-used, signed software runs normally. Something counts as new when it is first seen on this Mac, recently published, unsigned, just downloaded, or written by an agent in this session.

  2. Step 2

    New things are contained by default

    They run inside the containment layer with a narrow allowlist. No model is involved in this step.

  3. Step 3

    A local model reviews what is left

    It reads the script or package and the chain that led to it, explains the event, and recommends allow, keep contained or block.

The rule: AI may tighten protection on its own. It may never loosen it.

The model reads text that an attacker may have written, so a prompt injection must not be able to grant access. Loosening a protection takes a decision from you. If the model is unavailable, steps 1 and 2 still apply.

Where the beta is. This is the design. Today, known-bad packages and hosts are blocked, containment applies to npm install scripts, and the model advises without choosing which protections apply. Containing all new code by default is not built yet.

One install

One app instead of six tools

Good defenses exist for each piece of this problem. Each is a separate tool with its own setup, updates and alert style, and most assume a security-minded developer.

What people install today

  • Package firewallblocks malicious packages at install
  • Sandbox runnerrestricts a command's network and files
  • Per-app firewallcontrols outbound connections
  • Agent hooks and scannerscheck agent actions and skills
  • Vulnerability scannerfinds outdated software
  • Secret and injection checkerslook for leaked keys and hostile prompts

Six installs. Six configurations. Six kinds of alert.

BoxCop

  • One installOne permission flow, and one place to see what was blocked.
  • Layers share contextBoxCop can tell you that a blocked connection came from an install script that an agent started. Separate tools cannot know that.
  • Plain-language explanationsEach block says why, what, who started it and what to do next.
  • Defaults that need no config fileWritten for people who will never read a script.

Five of the six categories are in the beta, each with limits listed below. Secret and prompt-injection checks are planned and not built.

Privacy

Local first

  • No account

    Download it and run it. There is no sign-up, token or enrollment.

  • Nothing uploaded by default

    BoxCop does not send your source, secrets, shell history or browsing anywhere.

  • A local model

    Triage runs on your Mac. What the model reads stays on your Mac.

  • Your data stays put

    Events, history and settings live in one folder on your Mac.

Limited macOS beta

What works today

BoxCop is a limited macOS beta. This table is the current state of each layer, including what it does not do. The app shows "Protected" only for layers that are enforcing.

LayerBuilt todayCurrent limits
1. Install gate Local registry firewall that blocks listed malicious npm and PyPI releases using a signed malware feed. Opt-in routing for npm and pnpm. Skill and instruction-file checks. No minimum release age. No pip or uv routing in the app. No checks for MCP servers or editor extensions. Skill checks match a narrow set of patterns.
2. Containment npm dependency install scripts run sandboxed. Network goes through a local allowlist proxy. Writes to shell and npm configuration are denied. Blocks are reported with the package and the agent. npm install scripts only. Nothing yet for agent-written scripts, downloaded programs, MCP servers, pnpm, Yarn or Python.
3. Outbound control Network extension that records each app's new connections with process and signing identity, and blocks hostnames on a bundled threat list. Exact-host reputation only. No per-app rules. No inspection of request contents or secrets. The list updates only with app releases.
4. Agent checks Pre-action hooks for Claude Code, Codex and Cursor that hold recognizable credential access, exfiltration and dangerous commands. Optional approval inbox for sends and spending, confirmed with Mac authentication. Hooks are cooperative: an effect hidden inside a script can get past them. No coverage of desktop agent apps. No prompt-injection detection.
5. Machine health Automatic inventory of apps, Homebrew, Python, npm and runtimes with reviewed findings. Guided updates for a small number of packages. Findings are hand-reviewed, not general CVE coverage. No checks of runtimes embedded in apps. No scan for plaintext secrets.
6. Smart triage A local model that explains held actions and reviews linked activity, citing what it found. Advisory only. It does not yet choose which protections apply.

BoxCop covers what it launches or routes, not every process on the Mac. Like any security tool, it can miss things and it can be wrong about a block. An open-source release is planned; the repository is private for now.
